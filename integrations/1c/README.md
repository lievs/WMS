# Обмен WMS ↔ 1С:УНФ

WMS хранит документы «Перемещение» и «Инвентаризация». Эта интеграция
переносит их в 1С:УНФ по кнопке «Синхронизировать» во внешней обработке —
без изменения самой конфигурации 1С.

## Что и когда выгружается

- **Перемещение** — только если в WMS оно завершено (`Завершить перемещение`)
  **и** принято на складе назначения (кнопка `Принято на складе`). Пока
  короб числится «в пути» — документ не выгружается, чтобы в 1С не попало
  то, что по факту еще не приехало.
- **Инвентаризация** — как только завершена в WMS.
- Документ, который 1С уже забрала и подтвердила (см. ниже), повторно не
  отдается — можно жать «Синхронизировать» сколько угодно раз, дублей не
  будет.
- Создаваемые в 1С документы **не проводятся** — только заполняются и
  сохраняются как черновик, чтобы бухгалтер/кладовщик проверил их перед
  проведением.
- Номер документа WMS передается в поле «Комментарий» создаваемого
  документа 1С (`WMS: PER-000123`) — по нему легко найти исходный документ.

⚠️ **Важный открытый вопрос**: перемещения WMS могут вести не только между
реальными складами компании, но и на виртуальные «склады-города»
(ОЗОН/ВБ, для плана отгрузок) — сейчас выгружаются вообще все завершенные
и принятые перемещения. Если в 1С такие отгрузки маркетплейсам должны
попадать не как «Перемещение товаров», а как реализация/другой документ —
скажите, добавим отдельную фильтрацию по признаку склада.

## Протокол

Токен доступа генерируется администратором в WMS: **Обмен с 1С** в меню
(только для админа) → «Сгенерировать токен».

### 1. Получить документы, ожидающие переноса

```
GET /integrations/1c/api/export
Заголовок:  X-1C-Token: <токен>
(или ?token=<токен> в самом адресе)
```

Ответ:

```json
{
  "ok": true,
  "movements": [
    {
      "id": 12,
      "number": "PER-000045",
      "date": "2026-09-05T10:00:00",
      "from_warehouse": "Основной склад",
      "to_warehouse": "Склад №2",
      "comment": "WMS: PER-000045",
      "lines": [{"barcode": "4600000000015", "qty": 5.0}]
    }
  ],
  "inventories": [
    {
      "id": 3,
      "number": "INV-000012",
      "date": "2026-09-04T18:30:00",
      "warehouse": "Основной склад",
      "comment": "WMS: INV-000012",
      "lines": [{"barcode": "4600000000015", "qty": 12.0}]
    }
  ]
}
```

Сопоставление товара — **по штрихкоду** (`barcode`) и количеству (`qty`),
как и договаривались. Артикул в этом обмене не участвует.

### 2. Подтвердить, что документы созданы в 1С

```
POST /integrations/1c/api/export/confirm
Заголовок:  X-1C-Token: <токен>
Тело (JSON): {"movement_ids": [12], "inventory_ids": [3]}
```

Это **id из ответа export**, не номера документов. После подтверждения
эти документы больше не попадут в `export`.

## Внешняя обработка 1С:УНФ

Готового .epf-файла тут нет — собрать его может только сама 1С:Enterprise
(Конфигуратор), которой в этом окружении нет. Вместо этого — рабочий код
модуля формы (`SyncWMS.bsl`) с одной кнопкой «Синхронизировать»: создайте
в Конфигураторе новую внешнюю обработку с формой, добавьте на форму
командную кнопку «Синхронизировать» и реквизиты формы `АдресWMS` (строка)
и `ТокенWMS` (строка, тип пароль), а в обработчик нажатия кнопки вставьте
код из `SyncWMS.bsl`.

Точки, которые нужно проверить/поправить под вашу базу (отмечены `// TODO`
в файле):

1. **Поиск номенклатуры по штрихкоду** — код ищет её в справочнике
   `Справочники.ШтрихкодыНоменклатуры` (стандартный для УНФ), но если в
   вашей базе штрихкод хранится иначе (например, прямо в реквизите
   `Номенклатура.Штрихкод`, или у товаров есть характеристики
   размер/цвет со своим штрихкодом) — поправьте именно эту функцию,
   остальной код ее не касается.
2. **Поиск склада по названию** — склады сопоставляются по совпадению
   `Наименование`. Если названия в WMS и 1С отличаются — заведите
   собственную таблицу соответствия или переименуйте склады для
   единообразия.
3. **Организация** в документах — код берет единственную организацию из
   `Справочники.Организации`, если она у вас не одна — нужно будет
   выбирать её на форме.

Файл написан с расчетом на стандартную конфигурацию 1С:УНФ — если у вас
есть доработки (нестандартные документы/реквизиты), эти места тоже
потребуют правки вашим специалистом по 1С.
